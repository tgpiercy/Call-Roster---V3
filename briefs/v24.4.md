# Brief: v24.4 - Install panel (tooling release after v24.3.2)

Graeme's brief of Oct 14, 2026, digested against the repo and decided the same day. Builds when v24.3.2 has run in Excel (the pre-release rule). v25 is the first release installed through it.

## Goal
Every install and its smoke checks run from one panel of buttons clicked in order. Each update ships a step list; the panel turns it into steps, runs the automatic ones (backup, code swap, compile, the update's macros) and records the manual ones as Pass / Fail rows. An install is a dated record that resumes after a close.

## Decided Oct 14, 2026 (Graeme, with the digest)
1. **The engine stays in `Roster Updater.xlsm`.** The panel, the step runner and every code-changing step live in `updater/modUpdater.bas` v4, the updater's own workbook. No roster code runs while the roster's modules change (v1 ran inside the roster and crashed Excel on Oct 12; the brief's `modInstall`-in-the-roster shape and its `selfupdate` step are dropped).
2. **The log lives in the roster**, on a hidden sheet `Install Log` (`tblInstallLog`: Version, Step ID, Kind, Status, When, Windows user, Note), written by the updater as plain cells. One record per install, older versions below. Non-admins never see it (`ApplyView`'s hidden-sheet list).
3. **Slot: v24.4**, installed once by hand (modUpdater v4 into the updater workbook; the roster side is a normal small release). v25 and everything after install through the panel.
4. **The hand checks ship as `test` steps.** Each release's `INSTALL-vNN.md` keeps "what's new" only; its manual checks (the C-rows of the v24.3.1 guide, the 2B filtered-cancel test) become Pass / Fail rows in `install-steps.txt`, with opener macros in a small `modSmoke` in the roster. `SmokeTest` stays a `macro` step.

## Pieces
| Piece | Where | What |
|---|---|---|
| `modUpdater.bas` v4 | updater workbook | Keeps v3's swap-in-place engine (backup, modules / forms / ThisWorkbook replaced in place, new modules imported, rollback, no-save flag, `UpdateFinished` / `UpdateDrop`, members' template). Adds: the **Install** sheet in the updater workbook (folder picker, groups and steps drawn from the list, one enabled button at a time, Retry / Skip-with-note), the step runner, the log writer, compile detection, the reopen step, the trust-access fallback. |
| `install-steps.txt` | zip root | The release's step list (format below). Generated by `tests/build_zip.py` from the repo: the `EXPECT` line from every `*_VERSION` constant and `EXPECTED_RELEASE`, the paste list from `paste-in/`, the macro / manual / test rows from a per-release `briefs/steps-vNN.txt` the build copies in. |
| `Install Log` sheet + `tblInstallLog` | roster | Made by the panel on first use (a plain sheet; the updater adds it through the Workbook object, no roster code). Listed in the roster's admin-only hidden sheets. |
| `modSmoke.bas` | roster | Scenario openers for `test` steps: `SmokeCallout(d, shift)`, `SmokePosting(unit, d, shift)`, `SmokeSwitch(d)`. They only open forms pre-filled; they never write the log. Stamped like every module. |
| `SystemCheckOK() As Boolean`, `SelfTestOK() As Boolean` | roster (modSystem, modSelfTest) | The same checks as a result instead of a MsgBox, so a `macro` step can mark itself. |

## Flow
1. Open the roster and `Roster Updater.xlsm` in the same Excel window. In the updater: Alt+F8 > `InstallPanel` (or its sheet's button). Pick the unzipped update folder. The panel reads `install-steps.txt`, finds the roster (v3's `UpdTarget`), reads its `Install Log` and draws the steps; a partly finished install of that version offers to resume at its next step.
2. Only the next step's button is enabled. A click runs one step and stamps OK with the time, or FAILED with the error text. A failure locks every later step until **Retry** or **Skip** (admin note required).
3. Code steps follow v3's order: backup -> swap (no-save flag set first) -> compile -> `UpdateFinished` saves. A failed compile = `UpdateDrop` offered, the old file untouched.
4. The last step writes "installed vNN" with the SystemCheck line into the log. Older versions' records stay below.

## Step list format
```
VERSION v24.4
EXPECT modOvertimeEntry=v24.4, modCalendar=v24.4, ...   ' from the repo's version constants; the panel checks each after the swap

[1. Prepare]
backup  | Save a backup copy
check   | Folder complete, roster found, versions noted

[2. Install code]
swap    | Replace modules, forms and ThisWorkbook   | modules/*.bas, paste-in/*.txt
compile | Compile VBAProject
finish  | Lift the save block and save, then reopen | reopen

[3. Run once]
macro   | System check          | SystemCheckOK
macro   | Self test             | SelfTestOK
macro   | Upgrade layout        | ApplyRosterLayout | confirm
manual  | Import Kronos once

[4. Checks]
macro   | Smoke test (practice copy)      | MakePracticeCopy | confirm
test    | Filtered cancel of a planned move | SmokePosting Phosphine +21 Days | Row added at B3, off again at B6, ranks 1,2,3 ...
test    | Leave word refused at New Posting | SmokePosting Cypure +7 Nights   | "Reason without 'STD'" and nothing created
```

| Kind | Does |
|---|---|
| `backup` | `SaveCopyAs` -> `Backup before vNN <yyyy-mm-dd hhmm> - <name>.xlsm` beside the roster (v3's backup). |
| `check` | Every file the list names is in the folder; the roster is open, writable, admin; the installed versions are written to the log for the record; modules in the project that the zip does not contain are listed, never removed. |
| `swap` | v3's `UpdRun`: in place, rollback on failure, no-save flag set before the first change. `modUpdater` itself is never touched. |
| `compile` | The VBE "Compile VBAProject" command (`CommandBars.FindControl(ID:=578)`) run on the roster's project; if the control is still enabled afterwards the compile failed: FAILED, "open Alt+F11, the line is highlighted", and `UpdateDrop` offered. The "did it finish with no message?" question stays as the fallback when the control can't be found. |
| `finish` | `UpdateFinished`. With `reopen`: the updater closes and reopens the roster (no `OnTime`: the updater's code keeps running), then resumes at the next step. |
| `macro` | `Application.Run "'<roster>'!<name>"`. A Function returning Boolean marks OK / FAILED itself; `| confirm` asks "Did it finish without a problem?" for macros that only report through a MsgBox. |
| `manual` | The instruction and a **Done** button. |
| `test` | Optional opener macro with arguments (`+21` = today plus 21 days), the expected result, **Pass / Fail** (Fail asks for a note). |

After `swap`, the panel compares `EXPECT` with each module's version constant through the roster's `SystemCheckOK` once it compiles; any mismatch is FAILED.

## Gotchas carried over from the brief, and what they become
- *Deferred remove / `modX1`*: not an issue. v3 swaps code in place; only genuinely new modules are imported, and an existing component of that name is never removed first.
- *Project reset clears module-level variables*: irrelevant to the updater's code (another project), and the roster's state is in `tblInstallLog`, not in variables. The roster's no-save flag is a hidden name, as in v3.
- *The running module*: `modUpdater` lives in the updater workbook; updating IT is a one-line manual step in the list ("import the new modUpdater.bas into Roster Updater.xlsm"), rare, never automated.
- *Trust access off* (another PC): `swap` and `compile` become `manual` rows that print exactly what to remove, import and paste; the panel says so once at the top.
- *Macros that catch their own errors*: `| confirm`, or a `...OK()` function where one exists (SystemCheck, SelfTest, UpgradeOTLogLayout).
- *The roster's own version of events*: nothing in the roster knows about the panel except the hidden sheet in `ApplyView`'s list and `modSmoke`. If the updater is lost, every step still has a by-hand equivalent in the markdown note.

## Done when
- A full install of v24.4 itself from its own folder runs end to end on a copy with every step OK or Pass, and `Install Log` holds the record.
- The same list runs as manual rows with trust access off.
- Closing Excel mid-install and reopening resumes at the right step.
- `tests/build_zip.py vNN vPREV` writes `install-steps.txt` into the zip from the repo and `briefs/steps-vNN.txt`; a zip without one fails the build.
- From v25 on, `INSTALL-vNN.md` is "what's new" plus "open the panel"; the step list is the install.
