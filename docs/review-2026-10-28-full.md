# Full code and systematic review - Oct 28, 2026 (v29.0.2, main 956d005)

Ten read-only reviewers each read one part of the system line by line (call-out core; postings and sign-ups; calendar and
eligibility; switches, leave and attendance; Kronos, the log, rollover and integrity; people, moves and keys; publish,
privacy and the members' file; open / save / backup / move / updater; Desk, Lite, receipts and reports; tests, the
Python mirror and the mock loader). Every HIGH and every alpha-risk MED below was re-read in the code before it went
into this file; those carry **(verified)**. Nothing in the repo was changed by the review.

**Baseline:** vbacheck OK (70 files, 2,063 procedures), shadowcheck 0, undeclcheck 0, callcheck 0, docscheck 0;
pytest 1,214 passed.

**Overall:** the core rules hold. Call order, charging, the 16 h rule, DST hours, the rest rule, the sick window,
provisional OT, the Kronos ledger, voids, the rollover's verify, the gates and the publish's privacy screen were traced
and found sound (the SOUND list at the end). The defects cluster in four places: **paths that start from a different
place than the usual one** (a call-back, Post all lines, Fix an entry, a NO TAKERS line); **the temporary Act as**;
**copies of the file** (read-only Save As, a backup opened by mistake, the hourly backup's view); and **the alpha's own
plan and data**, where about ten expected figures will not match what the code does.

Severity: **HIGH** = a wrong charge / order / hours, data loss, a privacy leak, or a crash on a common path;
**MED** = wrong on a plausible edge or misleading on a data path; **LOW** = the rest.
**ALPHA** = would break or mislead the Nov 1-14 alpha. **NOW** = affects the real roster today (v29).
