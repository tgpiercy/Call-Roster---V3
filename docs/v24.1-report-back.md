## Findings that change the plan
1. **No free column beside Refused.** I = Refused, J = Seniority, and everything from J on is addressed by constants. Columns AU and AV are free and travel with sorts, but the filter stops at the last pay period, so a drop-down sort would leave them behind unless the filter is widened; they also sit at the far right, after the hidden 27th-period column. Decision 1.
2. **Two different "this year" tests.** The roster counts a charge by its **Period Start**; the members' `dLog` is filtered by **Shift Date**. They differ only for a shift in the last days of December that falls in next year's first period. The split and the report will use Period Start (the roster's rule), and `dLog` gets the same test so members' sub-totals match the roster.
3. **The master's calendar is not "two halves per day".** It is week rows; each day is two columns (who's off | covered by) with the day lines stacked above the night lines, a date row showing which crews are on, and it is picked by unit **group**, not unit. The members' data is per unit. Plan: publish the group list and the day / night crews in `dMeta` / `dCal`, and offer the master's groups plus the single units in the members' picker, so the two calendars can be compared side by side.
4. **Find me must not be baked into the published file.** The master runs the members' redraw during a publish, on the admin's login. "Remember me" is applied only when a member opens the file, and the publish always saves the neutral A - Z view.
5. **Sign-up needs two things on plant PCs:** macros enabled for the members' file (already true for its buttons), and **write access to the Signups folder** for every member. The members' file itself is never written. If the folder isn't writable the button says to use the paper sheet. While everything is local on your desktop this can only be tested with your own login.
6. **Who signed up.** The inbox records the Windows login, but plant PCs are shared, so the login can't prove who clicked. The master shows it to the supervisor and never publishes it. A sign-up is a request; the supervisor's tick is what counts.
7. **Call-outs have no "positions" and no order of answers.** The form lets outcomes be recorded in any order and more than one Accepted. "Hours still on offer" therefore has to follow **call order**: someone below a partial acceptance in the list was offered the remainder. Decision 3.
8. **Planned unit moves are the biggest item.** They touch `LoadEligible` (a person appears on a unit's list with a code the roster doesn't hold yet), the on-open path, Needs Attention and the Employee pop-up, and they need their own review round. Decision 5 offers them as v24.2.
9. **Publish reminder.** The close event already switches views and saves. The reminder runs before that, only for an admin on the writable live file, and a failed or declined publish never stops the close.
10. **Template version check.** `dRoster` gains two columns, so an old members' template would misread every column after Refused. The publish will refuse a template whose version is older than M2 and say "rebuild the template".
11. **Old `Refusal Report` leftovers.** `REFUSAL_SHEET` is still a constant and SystemCheck still flags a module called `Refusal_Report` as a leftover. The new report reuses the sheet name and lives in a new procedure; the old module stays banned.

## Decisions (Graeme, Oct 12, 2026)
| # | Question | Answer |
|---|---|---|
| 1 | Where the two Refused figures go | **Status line + members only.** The roster keeps its columns: no new formulas on the roster, nothing for the rollover or `AddRosterRow` to carry. Selecting a row shows that person's split on the status line; the members' file and the Refusals report show it for everyone. |
| 2 | Members see who signed up | **Names, as on paper.** |
| 3 | Call-out refusers after a partial acceptance | **The hours on offer**, by call order: 12 x 1.75 above the partial acceptance, the remainder x 1.75 below it. Postings stay at the full posting hours. |
| 4 | Unit moves ahead of time | **Planned moves, as v24.2**, built right after this release. Not in v24.1. |
| 5 | Find me remembers the person | **No, always pick.** Nothing is stored per login (finding 4 no longer applies). |
| 6 | "Other" hours (adjustments, opening balance) | **Shown only when not zero.** |
| 7 | Postings in the members' file (added later the same day) | After Find me: the postings the person is **qualified for**, listed ones first, then out-of-department ones (a code in the unit but not on the list). Plus **one plain table of all open postings**. |
| 8 | Sick time in the members' file (added later the same day) | **Counts only, for the picked name:** days used, paid days left, occurrences, personal days, and whether paid sick is available. No dates. This is a deliberate, narrow exception to v22.1's "attendance is never published". |

What decision 1 changes in the plan: build item 1 shrinks to the pure `RefusedSplit`, a status-line read for the selected row (one pass over the log for that name, on selection change, admin and non-admin alike), the two published columns and the IntegrityCheck line "call-out + posting + other = Refused". Build item 8 moves to v24.2.

What decisions 7 and 8 add: the publish gains a `dAttend` table (counts only, with its own privacy self-check) and per-posting sign-up counts; the members' Postings sheet is rebuilt around "my postings" and a one-row-per-posting table. "Qualified" is read from published values (on the list, or holding a code in the unit); the members' file never works out who is free.
