## v24.3 - unit moves entered ahead of time; Roster Updater v3 (built Oct 2026)
Brief: `briefs/v24.3.md`. Report-back, decisions and the pre-release review: `docs/v24.3-report-back.md`. Install: `INSTALL.md` in `dist/Callout_Roster_v24.3.zip` (full set). Needs v24.2. The members' template is not touched.

- **Planned unit moves** (`modPeople`, new sheet `Planned Moves` / `tblPlannedMoves`, made on first use). Employee > Move to unit with a date after today changes nothing on the roster and writes one Planned row. Lists built for a shift on or after that date already treat the person as moved: `LoadEligible` asks `UnitCodeOn` for each code, so they are off the cleared units' lists and on the new unit's with the planned grade code. Call-outs, posting lists, out-of-department candidates, the printed roster and the switch pick list follow because they already pass the shift date.
- **Listed at the hours they would have after the top-up** (`PlannedListHours`): the highest total among the others at grade 2 and below in that unit, never under their own. For call order only: the call-out pop-up and the printed call-out roster mark it `~`, and a call-out's OT Log row records the roster's real total (`EmpRec.RosterHrs` / `EstHrs`). A posting made in that window freezes the estimate on its list, as it freezes everyone's hours.
- **Applied on open.** The first admin open on or after the date runs every due move through `ComputeUnitMove` (hours as of the effective date) and `SaveUnitMove`: one backup, one save, one box. A move that can't be applied stays Planned with the reason in its Note. `ApplyPlannedMoves` (Alt+F8) does it by hand.
- **Cancel, never edit.** Needs Attention has a "Planned unit moves" block; double-click a line to cancel it (or apply it when due). A cancel removes only that move's `Exempt - moves <date> (PM-000n)` marks from open postings and puts back a crew change entered with it. Postings made while the move was waiting keep their frozen lists: on the new unit's the person is marked `Exempt - move cancelled (PM-000n)` so they are never charged, and the box names the old unit's postings made without them.
- **Crew dated at entry.** A crew change that comes with a planned move is written to the Crew History when the move is entered, dated the day of the move, so "scheduled" and the rest rule are right for later shifts.
- **Rename** carries the planned row; **Remove** cancels it first; a **second move** for the same person is refused until the first is cancelled or applied.
- **Postings.** The out-of-department award's "signed off in the unit" test and Reopen Posting's "no longer holds a code" test read the code as of the shift date; Reopen drops the mark of a move that was cancelled since.
- **Members' file.** Who's next loads its lists per date when a planned move falls inside its window; otherwise the publish is unchanged. Nothing else about a planned move is published.
- **IntegrityCheck** check 11: a waiting move for someone not on the roster, to an unknown unit, with no date, or more than 3 days overdue. **SystemCheck** shows how many are waiting.
- **SmokeTest** has 14 steps: step 9 plans a move for tomorrow, checks the roster row is untouched and both units' lists follow the date, cancels it and checks the lists go back.
- **Roster Updater v3** (`updater/modUpdater.bas`; re-import it into Roster Updater.xlsm by hand). v2's first real run (`UpdateMemberTemplate`, Oct 13) said "No roster is open" with the roster open. The roster is now recognised by its code OR by its OT Log table, a component whose name can't be read no longer stops the search, and when nothing is recognised the box lists every workbook Excel can see with the reason beside each and offers the workbook in front. The cause of the v2 miss is not known; that box will show it.
- SystemCheck: 22 modules on v24.3; `frmEmployee` and `frmOvertimeEntry` v24.3 (the two re-pastes). SelfTest 392 cases in 47 suites (+28): `plancode`, `planhours`.
- From the v24.2 install (Oct 13): by-hand install, SystemCheck, SelfTest and SmokeTest all passed on Graeme's copy. The only fault was the updater's roster search.

## v21 - call order accuracy (Oct 2026)
Brief: `briefs/v21.md`. Install notes: `INSTALL.md` in `dist/Callout_Roster_v21.zip`.

- **Provisional accepted OT.** An Accepted call-out or Awarded posting counts in Total Hours (G) from the moment it is logged, until Kronos covers the shift. The amount is the row's shift hours (not x 1.75), non-void rows in the roster year only. A day shift is covered once its date is on or before the Kronos data-through date; a night shift once the next day is. The import stores the data-through date (file date minus one) on every Hours History row and in the hidden name `KronosDataThrough`; column C on the roster (hidden) holds the provisional total per person and G = H + I + C. The call-out form marks such totals with `*`, the posting form says how many, the printed posting footer says so.
- **DST nights.** The night starting the Saturday before the first Sunday in November is 13 h; the Saturday before the second Sunday in March is 11 h (worked out by rule for any year). New Posting and Log Call-Out default Hours to the actual length on those nights when the shift is Nights and show a warning. Setting `DST_USE_ACTUAL_HOURS` (True).
- **Home Unit** column (B) on the roster with a drop-down of the eight units. `SetupHomeUnit` fills in anyone with a code in exactly one unit; SystemCheck and Needs Attention list the rest. Used by v22 and v24; nothing else reads it yet.
- **Adjustment types.** Add Adjustment asks for a type (Leave return / Unit move / New hire / Correction / Other), stored in the OT Log's Reason column.
- **Grade change log.** Changing a unit code on the roster writes a row to `tblGradeChange` (hidden admin sheet Grade Log; `ShowGradeLog`): timestamp, employee, unit, old code, new code, Windows login. Sorting, filtering and macro writes create no entries.
- **Daily backup.** The first admin open each day saves `Call Out Roster yyyy-mm-dd.xlsm` into `BACKUP_FOLDER` and deletes copies older than 30 days there. Never blocks opening; SystemCheck says when the folder isn't set or can't be reached.
- **SelfTest** (Alt+F8): 147 known-answer cases over rotation, holidays, DST, call order, charging, eligibility and provisional coverage, in memory only. The same table (`tests/cases.csv`) drives the Python mirror in `tests/`.
- **Printed call out roster.** The Call Out Roster button redraws the Blank Call Out Roster sheet from the data: title block with pay period and Kronos status, one section per unit in call order (#, Hours with `*` for provisional, Name [code], Crew, Phone), page setup done, then offers to print. It replaces the old macro that sorted the roster unit by unit and copied the chunks. Roster column A is hidden (empty); B shows Home Unit.
