# v27.5 - the three rule fixes found while reading for v27.1

Decided Oct 25, 2026 (`docs/v27.5-report-back.md`). Built on v27.1 (41 modules). Ships as soon as it is built and
reviewed; the alpha findings (Nov 1-15) become v27.5.5. Three items, one commit each, a SelfTest suite or cases for
each, the Python mirror kept in step (`tests/test_drift.py`).

## Item 1 - the 16 h hard stop on a same-day sister swap (modShiftSwitch, modCalendar)
Rule (Graeme, Oct 25): in a two-way switch on the same day each person must fit the 16 h rule on the shift they
WORK; the shift each one GIVES UP is treated as not worked (it is the other's now). A hard stop, worded like every
other switch stop. The same relief applies to a two-way payback on another day (the given-up shift on d no longer
counts as worked when the payback on d2 is read), which removes a false "16 h rule" stop on an adjoining-shift
payback.
- modCalendar: a pending give-up (name, date, shift) - `SetPendingGiveUp` / `ClearPendingGiveUp`, Private state -
  that `WorkedHoursOn` reads as 0 h. Set only inside `SwitchSaveStops`, cleared on every exit path (an error
  handler clears it too).
- modShiftSwitch: two facts `SF_S_FAT_WORKS` (the one working shiftLbl, with sh2 on d given up) and `SF_S_FAT_OFF`
  (the one giving up, working sh2 on d, with shiftLbl given up); `SF_N` 19. The payback read `f(SF_P_FAT)` runs with
  (offName, d, shiftLbl) pending. `SwitchStopsCore`'s same-day branch appends `FatigueStopText` for both.
  `SwitchWarnings` unchanged (the rotation warnings stay off for a sister swap: each one IS scheduled that day).
- Cases (`switchstop`): same-day worker 16 h stop; same-day giver 16 h stop; both; "on OT" on the shift worked;
  the given-up shift does not stop (fact blank). Mirror `tests/rules.py` switchstop updated.
- Doc: CLAUDE.md's 16 h row loses "a same-day sister swap skips it - a known gap, v27.5"; the Rules sheet's text
  for the 16 h rule says switches of every kind.

**After the reviews (Oct 25, Graeme):** the one-way switch stops too when a SCHEDULED shift beside the one worked puts it
past 16 h (the arithmetic, `FatigueShiftReason`, replaces `NotFreeReason` for every switch); the **same-day sister swap of
both shifts is EXEMPT from the arithmetic** (the review showed the rotation puts one of the two on 24 h on every cycle
day; it is the only swap an A/B pair can make) - of its two facts only "on OT" stops it. Suite `fatshift` proves the
pending give-up on the rotation (SelfTest's CaseFatShift, the mirror composes FatigueInputs).

## Item 2 - the missed morning named at the year-to-date import (ImportKronosData)
Rule (Graeme, Oct 25): when the one-day reports between the old Totals' Through and the new one have a gap, a
person's difference at the year-to-date import is a "gap" row (kind "gap", Note "no one-day report for <days>",
dated at the new Through), not an "edit". `RebuildWorkedPeriods` counts a gap row only while the ledger holds none
of the named days for that person; once a backfilled day arrives, the day's rows count and the gap row is set aside.
- `WriteCumulative`: the missing days in (oldThrough, ToD] from the ledger's day set (the quiet-day marker counts as
  held); when any are missing, `LogChanges` is called with kind "gap" and the days' list in the Note; the Transactions
  dating is skipped for a gap row.
- `RebuildWorkedPeriods`: pure `GapCountsCore(gapDays, heldDays)` = True while none of the gap row's days is held
  for that person (suite `kgap`). The gap row's weighted change lands in the Through date's period as before.
- The import message names the gap ("Oct 14 had no one-day report: its hours are in Worked Periods as a gap row
  until it is imported"). IntegrityCheck's Kronos line already names the gap in H's run; it adds the gap rows count.
- Cases: `kgap` (counts while none held; set aside once one is held; two gaps; a day held for a different person
  does not set it aside). Mirror `tests/rules_kronos.py`.

## Item 3 - the staffing count's partial covers (modMinStaff)
Rule (Graeme, Oct 25): the covered count of a shift = the shares of EVERY line added once, blank " / " parts
skipped, rounded DOWN; when a fraction was dropped the flag reads "SHORT 1/2 (part)". A giver the rotation did not
put on the shift but who gave it up in a switch counts scheduled-and-off (token "SW"), so the S/S line nets to zero.
- `CoveredShare(rt) As Double` replaces `CoveredCount` (per line, no rounding); `StaffCountsCore` sums and rounds down
  once, returning a `part` flag (ByRef Boolean); `StaffShort` takes `part` and appends " (part)".
- `StaffCounts`: a name with `SwitchOffOn(nm, d, shiftLbl) <> ""` is tokened "SW" even when `onShift` is False.
- Cases: the 16 `staffcount` cases re-derived (edge-two-partial-lines-round-each -> 1; edge-empty-part-counts-one ->
  2; partial-rounds-up -> 0 (part); two-half-partials-one-person -> 1; partial-plus-whole 9h + whole -> 1 (part));
  new: giver-not-on-shift-nets-zero; three-four-hour-parts-one-person. Mirror `tests/rules.py` staffcount.
