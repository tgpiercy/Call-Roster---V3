## Gap 1 - a same-day sister swap never runs the 16 h stop

**What the code does.** `SwitchSaveStops` (modShiftSwitch.bas:528) reads every fact, the 16 h one included
(`f(SF_FAT)` = `NotFreeReason` for the one working the shift). The pure `SwitchStopsCore` (:563) then, for a two-way
switch on the SAME day, sets `stops = ""` (:571) and keeps only bookings and other switches that day. The 16 h stop and
the rest-rule warning (`SwitchWarnings` skips `WorksConflict` for a same-day swap) are both set aside. Case
`switchstop,same-day-sets-the-one-way-stops-aside` pins the as-built behaviour.

**Why it was set aside.** In a same-day swap each person is SCHEDULED on the shift they give up, and the switch is not
saved yet, so `WorkedHoursOn` (modCalendar.bas:953) still counts the given-up shift as worked. For the one taking
Days on d, the next work is "Nights d" = 12 h away: `FatigueMaxHours(12 worked before?, 12 to next)` gives at most
12 - 11 = 1 h, so EVERY same-day swap would fail the stop. The relief of the given-up shift is the missing piece.

**The real case the rule exists for.** A nights-crew person who worked Nights d-1 (19:00 to 07:00) and swaps into
Days d (07:00 to 19:00) works 24 h straight. Today nothing says so: no stop, no warning.

**Options.**
- **A (recommended): the hard stop, for both people, on the shift each one WORKS, with the shift each one GIVES UP
  treated as not worked.** Mechanism: a short-lived "pending give-up" (name, date, shift) in modCalendar that
  `WorkedHoursOn` reads as 0 h, set by `SwitchSaveStops` around its two `FatigueReason` reads and cleared on every
  exit path (the same idea as `PaybackProblem`'s rest-rule relief at :484-487, which exists because the relieving
  switch is not saved yet). Two new facts `SF_S_FAT_WORKS` / `SF_S_FAT_OFF` worded by `FatigueStopText`; the
  same-day branch of `SwitchStopsCore` appends them. The stop reads "- Bob would go past 16 h of work with the OT
  accepted around Nov 2 days (the 16 h rule)" like every other switch. Cases: the Nights d-1 then Days d swap
  stops; a clean swap passes; the given-up shift does not count against either person; OT accepted on the shift
  worked still stops ("on OT").
- **B: a warning in the confirm, saved over** (as the rotation warnings are). Same facts, shown under "Warnings",
  no stop.
- **C: leave it exempt** (as built): the supervisors judge a sister swap themselves. Documented in CLAUDE.md as the
  one switch the rule does not test.

**Companion to check in the build (no decision needed):** a two-way switch whose payback is the ADJOINING shift
(Nights d given up, Days d+1 paid back) relieves the rest rule in `PaybackProblem` (:484-487) but the 16 h read
there still counts the given-up Nights d as worked, so a legitimate payback can hit a false "16 h rule" stop. The
same pending-give-up relief fixes it; a case will prove it either way.

## Gap 2 - a missed Kronos morning counts twice in Worked Periods

**What the code does.** A one-day report missed (no import for day X). At the period end the year-to-date report
arrives: `WriteCumulative` (ImportKronosData.bas:1401) compares the new Totals with what the ledger expected (old
snapshot + the ledger days after it) and logs every difference through `LogChanges` (:1450) as kind "edit". The
difference is day X's hours, but nothing names day X: the Transactions block holds timecard EDITS, not worked days,
so the row is dated at the report's Through (:1482 only moves the date when an edit names the day).
`RebuildWorkedPeriods` (:1563) then adds that "edit" row to the Through date's period (`EditCountsCore`, :254).
If day X's one-day report is imported later (a backfill), `WriteLedgerDay` (:1337) adds the day's rows and the
rebuild counts them too: the first import of a day writes no "day" change row, so `EditCountsCore`'s re-import test
does not fire and the "edit" row stays counted. Worked (H) is RIGHT either way (`PivotFromLedger`, :1497, reads
the snapshot + the run, never the edit rows); only Worked Periods (published to members as dWorked, shown in My
history and the history report's pay-period block) is high by day X's hours.

**Options.**
- **A (recommended): name the gap at the year-to-date import.** When the ledger run between the old Through and the
  new Through has missing days, a person's difference is logged as kind "gap" (Note "no one-day report for Oct 14,
  Oct 15") dated at the Through, not "edit". `RebuildWorkedPeriods` counts a "gap" row only while the ledger still
  holds NONE of its named days for that person; once a backfilled day arrives, the day's own rows count and the
  gap row is set aside. Nothing lost, nothing double. A genuine timecard edit across a gap is folded into the gap row
  (it cannot be told apart without the day); the Worked Changes sheet says so. Pure core `GapCountsCore` + suite.
- **B: never count the difference across a gap in Worked Periods.** The late day counts when it arrives; if it never
  arrives, that period's Worked Periods stays low (H right, IntegrityCheck already names the gap). Simplest.
- **C: as built, documented.** My history can show a period high after a missed morning that is later backfilled.

## Gap 3 - the staffing count's partial lines

**What the code does.** `StaffCountsCore` (modMinStaff.bas:258) sums `CoveredCount` (:285) per calendar line.
Three edges:
1. **Two partial lines round up separately.** "Joe D 6h" on one line and "Sam K 6h" on another = 2 covered; the same
   two on ONE line ("Joe D 6h / Sam K 6h") = 1. Case `edge-two-partial-lines-round-each` pins it.
2. **An empty " / " part counts a person** ("Ann B /  / Cal D" = 3). Case `edge-empty-part-counts-one` pins it.
3. **A switch saved over the "isn't on that shift" warning** counts the worker's S/S line as covered without counting
   the giver as off (the giver's token is "" when the rotation does not put them on the shift, :234), so the count
   is one high.

**Options.**
- **A (recommended): sum the shares of every line on the shift ONCE, skip blank parts, and round DOWN, with "(part)"
  in the flag text when a fraction was dropped.** A 6 h cover of a 12 h shift is 6 h short, so "SHORT 1/2 (part)"
  tells the truth; "Joe D 6h / Sam K 6h" across one or two lines = 1 either way. Edge 3: a giver the rotation did
  not schedule but who gave the shift up is counted scheduled-and-off (token "SW"), so the S/S line nets to zero and
  the count stays what the rotation says. Rows changed: the 16 `staffcount` cases re-derived, `StaffShort` gets the
  part flag.
- **B: sum once and round UP** (the v26 intent, only the per-line rounding and the blank part fixed). A 4 h cover
  still counts as a whole person for staffing. Edge 3 as in A.
- **C: leave as built.**
