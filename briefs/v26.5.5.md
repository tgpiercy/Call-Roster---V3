## Items, in commit order

### Integrity
1. **A failed save is reported (A1).** `SaveIfWritable`: capture `Err` after `ThisWorkbook.Save` and compare `FileDateTime(ThisWorkbook.FullName)` before and after; on failure `LogError`, a blocking box "NOT SAVED to disk (<reason>). Don't close Excel. Try File > Save; if that fails tell <PRIMARY_ADMIN_NAME>.", and return False so the pop-ups keep their entries (the call-out and award paths show the box and do NOT reset the form). `BeforeClose` the same pattern (the box, then the close is cancelled). The Desk header shows a red "Not saved since 3:14 AM" while `ThisWorkbook.Saved` is False after a submit (one read in `DrawDesk`). SmokeTest: no new step (SmokeTest never saves); the pure part is nothing.
2. **A stale copy blocks the save (A2).** `Workbook_Open` records the file's on-disk mtime in a module variable (`gOpenedMtime`) and every own save updates it (`SaveIfWritable`, the rollover, `SaveRestrictedCopy` excluded: a copy is not the master). `Workbook_BeforeSave`: if `FileDateTime(FullName)` differs from the record, `Cancel = True` and the box "Someone else saved this file at <time> while you had it open. Close WITHOUT saving, reopen, and log your entry again. Nothing you did here was written." `MarkNoSave` so the close path cannot save either. Read-only copies and `gSmokeRun` skip it. (verify) that SharePoint's sync client reports a changed mtime on the local path; if not, fall back to a hidden name `SaveStamp` written on every own save and compared on open.
3. **Esc-safe writes (A3).** `QuietOn` sets `Application.EnableCancelKey = xlErrorHandler`; `QuietOff` and `ReportError` restore `xlInterrupt`. Every writer that does not use `QuietOn` (`AppendLogRows`, `VoidRef`, `SyncKronosData`'s H loop) sets and restores it itself. `ReportError` treats Err 18 as any other error (the message says "Stopped by Esc" in the Error Log's Detail). callcheck's RESTORE class learns `EnableCancelKey` (a set with no restore is a finding).
4. **An error in Total Hours refuses to load (A4).** `LoadEligible`: if `IsError(v(i, C_TOTAL))`, or `IsError` on `C_REFUSED` / `C_PROV` when provisional OT is live, `Err.Raise` "Total Hours shows an error for <name>. An admin runs Alt+F8 > RefreshRosterFormulas, then try again." The call-out and posting pop-ups show it through their handlers. `BuildRoster` (publish) the same, so the members' file never carries a 0 that is an error. `RefusedFormula` references the name through `ThisWorkbook.Names` so a copy with the name missing shows `#NAME?` (it already does) and is now refused rather than mis-ordered. Pure: nothing (a sheet read).

### The rule change
9. **Accepted OT is a worked shift: the 16 h rule (1.1).** One new reason in `NotFreeReason` (modCalendar), after the rest rule: **"16 h rule"** when the hours on offer, added to any shift the person works that touches it (their scheduled shift per the rotation, an accepted call-out, an awarded posting, a switch worked, on the same date or the adjacent one), would exceed 16 consecutive hours, or would leave less than 11 h before their next scheduled shift. Worked OT is read from Coverage (non-void lines naming the person, with the hours from the log row) through one new reader `WorkedOtOn(emp, d, shift)`; a shift given up in a switch counts as rest (as D-C3). Pure core `FatigueProblem(scheduledBefore, scheduledAfter, otBefore, otAfter, hoursOffered, gapToNext)` returning "" or the reason, mirrored in `rules.py`, suite `fatigue` (12+ cases: the 12 + 4 partial, 12 + 8 refused, a night then a day, a day then a night, the switch given up, the 11 h gap). `FilterNotFree` counts it; the call-out card shows "16 h" as the reason; the printed roster and Who's next leave the person off as every other reason. **Max hours per person:** `LoadEligible` returns `MaxHours` (16 minus the touching work); the call-out and award pop-ups grey a person whose max is below the hours on offer and show "max N h" beside the name; a partial award at or under the max is allowed. CLAUDE.md's not-free table gains the row; the system manual's eligibility section too. Members M4 publishes the reason word ("16 h rule") in `dNotFree` later; nothing in the members' file changes now.
