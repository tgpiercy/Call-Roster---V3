## Item 1 - members' requests (R): time off and shift switches asked for from the members' file
**Rules (Graeme):** admins only act on a request; a switch request reaches the admin only after the named partner has
clicked Agree in the members' file on their own PC; a request writes NOTHING on the roster by itself - the admin's save
through the existing pop-ups does (their rules apply: bookings, the sick window, the 16 h stop); the Note is never
published; only "Time off" is ever published as a kind.

### Members' side (Members M5; `member/modMember.bas`, the template rebuilt at install)
- Home: two buttons under the tiles, **ASK FOR TIME OFF** and **ASK FOR A SWITCH**, both opening the `Requests` page.
- The `Requests` page: typed cells - Kind (Time off / Switch, a list), From, To, Shift (Days / Nights; switch only),
  Partner (a roster name, a list; switch only), Note (free text) - and **Send**. Send checks the cells (dates typed through
  the members' own simple date read - the file holds no rules, so a plain `IsDate` + whole-day; From <= To; a partner
  for a switch who is not me), screens the Note for the leave words (`LeaveWordsIn`'s list mirrored as text in the
  file, as the Reason box does), then writes `REQ__<login>__<yyyymmdd-hhnnss>.txt` into `Requests\` beside the
  members' file (`REQUEST_FOLDER` ".\Requests"; made if missing): `kind=`, `employee=`, `from=`, `to=`, `shift=`,
  `partner=`, `note=`, `login=`, `stamp=`, `action=request`. A switch request also writes `agree=waiting`.
- **Agree (switch):** the named partner's PC shows the request under **Asked of me** with an **Agree** / **No** button;
  Agree writes `REQ__<id>__agree__<login>__<stamp>.txt` (`action=agree`, `partner_login=`); No writes `action=refuse`.
  The master takes a switch request only once an `agree` file from a DIFFERENT login than the requester's exists.
- **My requests:** the member's rows from the published `dRequests` (Kind, From, To, Shift, Partner, Status, the admin's
  Answer line, Decided) + **Withdraw** (a file with `action=withdraw`). Statuses: Waiting for partner / Waiting /
  Booked / Declined / Withdrawn / Expired.
- `MEM_VERSION` "Members M5", the How-it-works page gains a section; the member's own request list is keyed by the
  remembered name AND the login (both must match for Withdraw).

### Master side (`modRequests`, NEW module; N_MODULES 42)
- `RequestsTable` (admin-only `Requests` sheet, `tblRequests`, made on first use): Request ID (`RQ-nnnn`, from the id
  marks), Kind, Employee, Login, From, To, Shift, Partner, Partner Login, Agreed At, Note, Status, Received, Decided By,
  Decided At, Answer, Ref (the `AB-` / `SS-` id it became), File. `ReadRequests` (Workbook_Open step for an admin; the
  Desk tile; Needs Attention's refresh) reads `Requests\`: a new request file -> a row Status "Waiting" (a switch
  without an agree file -> "Waiting for partner"; with one -> "Waiting"); `withdraw` -> Withdrawn; `refuse` ->
  Declined by partner; a request whose To is past -> Expired. Pure cores: `RequestFileCore` (the file's lines -> a
  row or a refusal), `RequestStatusCore` (request / agree / refuse / withdraw files -> the status), suite `request`.
  Files of decided / withdrawn / expired requests are moved to `Requests\done\` (as `ArchiveSignups`).
- **Needs Attention**: section "MEMBERS' REQUESTS - waiting for an admin (double-click: book it; right-click: decline)",
  one row per Waiting request (the name, the kind, the dates, the partner, received when). Double-click: time off ->
  `frmTimeOff.Prefill name, from, to` (+ the request id in a module variable the save reads) then the pop-up;
  switch -> `frmShiftSwitch.Prefill offName=the member, worksName=the partner, d=from, shift` (two form re-pastes).
  The pop-up's save calls `modRequests.MarkBooked id, ref`; a Cancel leaves it Waiting. Right-click / the menu:
  **Decline** takes a reason (the Answer line, screened for leave words) -> Declined. A receipt after each.
- **Desk (admin)**: a tile "Requests waiting (N)" opening Needs Attention on the section. **Publish**: `dRequests`
  (Employee, Kind "Time off" / "Switch", From, To, Shift, Partner, Status, Answer, Decided) through `WriteTable`,
  screened (`LeaveWordsIn`, `PrivateDataIn`: no login, no note); `MEMBER_NEEDS` "Members M5". IntegrityCheck: a
  Booked request whose Ref is void or missing -> Check.
- Settings: `REQUEST_FOLDER` ".\Requests" (beside the members' file, as `SIGNUP_FOLDER`), `REQUESTS_ON` True.
- Cases: `request` (the file parse, the agree rule - the same login does not count -, withdraw, refuse, expired,
  the status words), the publish screen (a leave word in an Answer refuses the publish).

## Item 2 - the Payroll # as the key (K): carry it everywhere, rename and match by it
**Rules (Graeme):** every people table carries the Payroll #; a rename and every lookup use the number when both sides
have one, the name otherwise; the roster's pay-period SUMIFS stay by name; a new hire's number is typed at Add (8
digits, checked, may be blank); the members' file never sees the number.
- A **Payroll # column** added on first use (as `FM_PAYROLL`) to: the OT Log (a verified layout step in the
  `UpgradeOTLogLayout` style - `L_PAYROLL` = 22, `L_NCOLS` 22; the log is append-only, the column is filled, no row
  moves; every log reader uses `L_*` constants), Posting lists, Absences, Shift Switches (gives up / works), Grade Log,
  Hours History, Crew History, Planned Moves, Restrictions, Evidence, Requests (born with it). Every writer stamps it
  (`PayrollOf(name)`: the roster's column A, then Former).
- **`AssignPayrollKeys`** (admin, run once; the Install panel's group 3): fills every blank key from the roster and
  Former by name, verified by `RosterTotalsMap` / `TotalsDifference` before / after and `MarkNoSave` on a mismatch;
  the rows nobody matches are listed on the Integrity sheet and left blank. **`FillPayrollKeys`** (after a Kronos
  import, after Add / Edit, after a rename): propagates a newly known number to that person's keyless rows.
- **`RenameEverywhere`** rewrites the display name BY KEY where a row has one (a row whose name was mistyped by hand
  is found), by name otherwise; `NameColumns` lists the display columns and their key columns side by side.
- **`EmpRec`** carries `PayrollNo`; `LoadEligible` and the planned-move / crew-history / restriction lookups match
  by key when both sides have it. The Employee pop-up (Add / Edit) gets a **Payroll #** box (digits only, 8 at most,
  blank allowed; a number already on another row is refused) - `SaveNewHire` / `SaveEmployeeEdit` write column A;
  the Kronos import keeps filling / confirming it (a mismatch = the import's clash rule, named).
- IntegrityCheck 16 "Keys": a key on two roster rows (PROBLEM), a row with a key the roster does not hold and Former
  does not either (Check), the count of keyless rows per table (Note).
- Pure cores: `KeyMatchCore(keyA, keyB, nameA, nameB)` (suite `keymatch`), `PayrollValid(text)` (suite `payroll`).
