## Items

### 1. Master: `modPublish` and the Member View button
- New module `modPublish` with `PublishMembers`. `PublishMemberView` (the button's OnAction, kept) becomes a one-line wrapper that calls it, so no button is rebuilt.
- Steps: build every data table in memory from the master; open the template (`Call Out Roster - Members TEMPLATE.xlsm`, next to the master; clear error if missing); clear and fill its very hidden data sheets with values; stamp `dMeta`; save as `Call Out Roster - Members.xlsm` in `PUBLISH_FOLDER`; close it. The master is never changed, so nothing in it is written or saved by the publish except the hidden name `MembersPublishedAt`.
- If the save fails (file open on a plant PC), save `Call Out Roster - Members yyyy-mm-dd hhmm.xlsm` beside it and say so.
- Settings in modOvertimeEntry: `MEMBER_TEMPLATE_NAME`, `MEMBER_FILE_NAME`; `PUBLISH_FOLDER` and `PUBLISH_REASONS` already exist.
- Privacy is enforced in the export code by construction: each table lists exactly its published columns; nothing copies whole rows.

### 2. Published data (very hidden sheets in the members' file, flat tables)
| Sheet | Columns |
|---|---|
| `dMeta` | Published at, Published by, Master version (`EXPECTED_RELEASE` + module stamp), Kronos data date, Kronos data through, Pay period start, Pay period end, Roster year from/to. |
| `dRoster` | Name, Crew, Home Unit, Total, Worked, Refused, Provisional, then per unit: Code, Position (1 = first called; blank when no code). Position = the person's rank in `LoadEligible(unit, "ALL")`, i.e. the master's call order. |
| `dNext` | Unit, Date, Shift (Days/Nights), Rank, Name, Total, Code. One row per free person, for each of the 8 units x next 14 days x 2 shifts, from `LoadEligible` + `FilterNotFree`. |
| `dCal` | Date, Shift, Unit, Left text (who's off / need, leave shown as "Leave"), Right text (coverage), Type code, Open flag. From `SlotsFor` for every date from the 1st of last month to the end of month +3, each unit. |
| `dPost` | Posting ID, Unit, Date, Shift, Hours, Positions, Reason, Closes; and `dPostList`: Posting ID, Rank, Name, Hours (posted). Open postings only. |
| `dLog` | Shift Date, Ref ID, Type, Unit, Shift, Employee, Outcome, Hours Charged, Period Start, Note (only when `PUBLISH_REASONS`). This year's non-void rows. |

### 3. Members' file: `modMember` + its ThisWorkbook
- `BuildMemberTemplate` (run once in a blank workbook after importing `modMember.bas` and pasting the ThisWorkbook code): creates Home, Roster, Who's next, Calendar, Postings, My history and the data sheets; draws buttons and controls; protects every sheet (macros only); saves nothing itself.
- Sheets:
  - **Home:** "Updated <dMeta> / Kronos data <date>", big buttons to each view, Find me box.
  - **Roster:** from `dRoster`. Buttons per unit (sorted by that unit's Position, no-code rows hidden), A-Z, Show all; crew filter; Find me highlights the row. Without macros: opens on Roster A-Z with AutoFilter on.
  - **Who's next:** unit, date (next 14 days) and shift pickers (data validation cells); the list from `dNext` for that key, rank order, with hours.
  - **Calendar:** month and unit pickers; days/nights grid from `dCal` in the master's colours (`TypeColor` values copied as constants); read-only.
  - **Postings:** open postings and each one's list from `dPost`/`dPostList`.
  - **My history:** name picker; that person's `dLog` rows newest first, with totals per pay period and the year.
- No rules in the member file: it only filters, sorts and looks up published values. The only arithmetic is summing charged hours by pay period on My history.
- `ThisWorkbook` (member): on open go to Home, redraw the open view from the data, show the published-at stamp; everything else is buttons.
- The two member files are kept in `member/` in the repo and the zip (`member/modMember.bas`, `member/ThisWorkbook.txt`), with their own version constant `MEM_VERSION` shown on Home.

### 4. Master: Needs Attention and SystemCheck
- Needs Attention gets a line "Members file last published <date> (<n> days ago)" under a small section when it is more than a day old or never published (double-click runs Member View).
- SystemCheck lists `modPublish` (13 modules on v21 M1) and reports the template presence and last publish.

### 5. Tests
- `tests/`: no new pure rules (the member file has none). A publish self-check in `modPublish` compares `dRoster` positions for one unit with `LoadEligible` order before saving (cheap, catches a wiring slip) and refuses to publish if any phone/email string appears in the exported arrays.

## Out of scope

- Sign-up through the members' file (paper stays).
