## 1. Attendance tab
Today `modAttendance.ShowAttendance` draws 13 columns for every roster name, worst first. Occurrences are one text cell ("Jan 5, Mar 2").

**DECIDED: one row per person, occurrence columns.**
- Columns: Employee, Crew, Home Unit, **Occurrence 1**, **Occurrence 2**, **Occurrence 3** (then 4, 5 ... only as far as the busiest person needs), Sick days, Paid, Personal, Sick + personal, Status, Until / restarted.
- Each occurrence cell: its dates and how many of its days were paid, e.g. `Jan 5 - 6 (2 days, 2 paid)` or `Mar 2 (1 day, unpaid)`. One line, no wrap.
- **Only people with at least one sick or personal day in their current window.** A "Show everyone" button draws all names.
- **Default order A - Z.** Sort buttons on the sheet: A - Z, By department (Home Unit, then name), Worst first (today's order). The department sort puts a light heading row or a band colour between units; pick whichever keeps the sheet filterable (a filter on the header row must still work).
- Keep: admin only, hidden in saved copies, never published, redrawn each time, no hours touched.
- Tidy: freeze the header, fixed column widths, status colour only in the Status cell, print setup landscape fit-to-width with the title row repeated.

**Rule work.** `AttendanceCore` returns only the first day of each occurrence (`OccDates`). It must also return, per occurrence: first day, last day, days, paid days. Add it to `AttendanceStatus` (fixed-size arrays in a Type are fine; size for 12 occurrences and say so if exceeded), mirror in `tests/rules.py` `attendance`, and extend the `attend` cases so the per-occurrence figures are checked. The counting rule itself does not change.

(verify) Occurrence numbering restarts when the counters restart after a wait; the sheet shows the current window only. Say so in the sheet's sub-title.

## 2. Refused split
Today roster column I (Refused) = SUM of the pay-period cells, and each period cell is a SUMIFS over the OT Log's Hours Charged by Employee + Period Start + not VOID. The log's **Type** column already says `Callout`, `Posting` or `Adjustment`.

**DECIDED: two roster figures plus the members' file. Refused stays the total and still drives Total Hours and call order. Nothing about charging changes.**
- **Call-out** = non-void Hours Charged, Type `Callout`, Period Start inside this roster year.
- **Posting** = the same for Type `Posting`.
- Everything else (Adjustments: `ADJ-`, `LV-`, `NH-`, `UM-`; `OB-` opening balance; `MAN-`) is in Refused but in neither figure. The check is `Call-out + Posting + Other = Refused` for every row; show "Other" only where it isn't zero (a third figure, or a cell note: builder's choice, ask if unsure).
- Formulas over the log, locked, written per row by one function next to `WriteRefusedRow`, and included in `ConvertRosterToFormulas`, `AddRosterRow` (modPeople), the rollover's header rewrite and IntegrityCheck's "Roster = log" check.

**Report-back item (decide before coding): where the columns go.** No column is free beside Refused. Options, in order of preference:
1. Columns **AU and AV** (free, inside the sort range `C_LAST`), with `EnsureRosterFilter` widened so a drop-down sort can't leave them behind. Shown by widening the frozen pane is NOT possible, so they sit far right: acceptable only if a button or the status line can also show them.
2. Insert two columns after I. This moves J..AT and every `C_*` constant from `C_SENIORITY` on, the period formulas, the 27th-period logic and the members' publish. It is a verified restructure (backup, change, compare every total, block the save): only if Graeme wants them beside Refused.
3. Keep the roster as is and show the split in the status line for the selected row plus the members' file.
Ask Graeme as a multiple-choice question with these three, option 2's risk stated plainly.

**Publish.** `modPublish.BuildRoster` adds `Refused call-out` and `Refused posting` after `Refused` (dRoster columns; `ROSTER_FIXED` grows, and `modMember`'s `RC_*` constants move with it: see M2). `BuildLog` already carries Type per row, so My history can total by type without new data. ## 3. Sign-up inbox (master side)
**DECIDED: members sign up from their workbook into an inbox; the master reads it; the supervisor still confirms. The paper sheet stays valid.** (verify with Graeme before go-live: the CBA wording is "initial beside your name". An electronic sign-up needs the same standing with the union and management. Build it; switch it on with a setting.)

- Setting `SIGNUP_FOLDER` (default `".\Signups"` beside the members' file, resolved like `PUBLISH_FOLDER`), and `SIGNUPS_ON As Boolean`.
- **One small text file per action**, written by the members' workbook (M2), so two people never write the same file: `P-0012__<login>__<yyyymmdd-hhmmss>.txt`, one line `key=value` each: posting, employee, hours (blank = whole shift), action (`signup` / `withdraw`), login, machine, timestamp. No rules in the file.
- **Award Posting > LOAD** reads the inbox for that posting, newest action per employee wins, and:
  - ticks Signed up (and sets PARTIAL HOURS) for names that are on the posting's frozen list;
  - lists, without ticking: names not on the list (out of department: they go in the Out-of-department box as candidates), actions stamped after the closing time, a login that signed up someone else's name more than once (shown, not blocked: a shared plant PC is normal);
  - shows a line under the list: "5 electronic sign-ups read (2 partial), 1 after closing, 1 not on the list". The supervisor can untick anything.
- On Submit / No takers / Cancel the posting's inbox files move to `Signups\Done\<posting>\`. Reopen does not bring them back.
- Each electronic sign-up that ends as an OT Log row carries `electronic sign-up <login> <time>` in the Note. Never published.
- New Posting writes nothing to the inbox. The posting must already be in the members' file (publish after posting; the existing "members' file is stale" reminder covers it).
- **Publish** adds per-posting sign-up status for M2: decide with Graeme whether members see **who** has signed up (the paper sheet shows it today) or only a count plus their own line. Default: names, as on paper.
- IntegrityCheck: a Check line for inbox files older than 7 days for postings that are closed.

## 4. Refusals report
A printable summary of the split in item 2, for union meetings and the monthly check.
- Alt+F8 / ADMIN button `RefusalsReport`: pick a unit (or all) and a range of pay periods (default: this year to date).
- One row per person: Call-out refused hours, Posting refused hours, Other (adjustments), Total, and the count of refusals of each kind. Sub-total per unit. Sorted by Home Unit then name; a second view sorted by total, highest first.
- Drawn on an output-only sheet (redrawn each time, like `Overtime Posting`), PDF to `ReportFolder()`, print landscape.
- Built from the OT Log in one pass (the same pure `RefusedSplit` as item 2), non-void rows only. No names of who logged a row, no notes.
- (verify) `REFUSAL_SHEET = "Refusal Report"` is still a constant in modOvertimeEntry and `Refusal_Report` is listed as a leftover module in SystemCheck: reuse the sheet name, don't revive the old module.

## 5. Publish reminder on close
With electronic sign-ups a stale members' file costs more: a posting that isn't published can't be signed up for.
- `Workbook_BeforeClose` (admin, writable, not a practice copy): if a posting was created, awarded, reopened or cancelled, or a person was added / moved / renamed / removed, since `MembersPublishedAt`, ask once: "The members' file is older than today's changes. Publish now?" Yes runs `PublishMembers`, then the close continues. No closes as today.
- Track "changed since publish" with a hidden name set by the existing write paths (one helper, called where `MarkCalDirty` is called for postings, plus modPeople's `AfterPeopleChange`). Never publish without asking; never block the close; a failed publish reports and still closes.

## 6. Partial hours on call-outs and out-of-department awards
v24 did partial hours for in-department posting awards only.
- **Call-out** (`frmOvertimeEntry`, designer layout: add controls in code only): an Accepted outcome can carry hours below the call-out's hours ("took 8 of 12"). The Accepted row's Hours = the hours taken (provisional OT sums that column). The form keeps the session open and shows "4 h still to cover"; calling continues down the list for the remainder, and the session ends when the hours are covered or the list is exhausted.
- **Charging (ask, default first):** people who Refuse or Left Message are charged the hours **being offered at that moment** x 1.75 (12 before the partial acceptance, 4 after) / always the call-out's full hours. This differs from postings (v24 charges the full posting hours) because on a call-out each person is offered a specific number of hours; state both rules side by side in the question.
- The calendar line shows each name with its hours, as v24 does for postings (`UpdateCoverageBySource` with `clearHours`).
- **Out-of-department award** (`SubmitAwardOutside`): an hours box beside the name; blank = whole shift. The out-of-department row carries the hours taken. The same order rule as v24: an out-of-department partial only when no in-department sign-up (full or partial) is left. In-department charging unchanged.
- `CalloutCharge` stays the one place the call-out charge is worked out; add the hours-offered argument there, mirror in `rules.py`, cases for a partial acceptance followed by a refusal.

## 7. Unit moves entered ahead of time
v24 refuses a future-dated unit move because roster unit codes aren't dated: changing a code changes every list at once.
**Proposed (ask, default first): planned moves, applied on the day.**
- `tblPlannedMoves` (admin sheet): Employee, New Unit, Grade Code, Codes To Clear, New Crew, Effective From, Entered By, Status (Planned / Applied / Cancelled).
- Employee > Move to unit accepts a future date: nothing on the roster changes; a Planned row is written; the confirm says so. Needs Attention lists planned moves; Cancel from there.
- On the first admin open on or after the date (`PeopleOnOpen`), each due move is applied through the SAME `SaveUnitMove` path (hours worked out as of the effective date, `UM-` Adjustment, Grade Log, crew row), with one summary message. A move that can't be applied (person removed, unit gone) stays Planned and is reported.
- Between entry and the date, lists for shifts **on or after** the date must already treat the person as moved: `LoadEligible(..., asOf)` leaves them off the old unit's list and puts them on the new unit's (with the planned grade code), and `ExemptFromOpenPostings` runs at entry time for old-unit postings dated on or after the move.
- The alternative, for the question: fully dated unit codes (`tblCodeHistory`, `CodeOn(emp, unit, date)` everywhere the unit columns are read). It is the crew-history pattern again but touches call order, sorting, the printed roster, the publish and the grade log; recommend against it for v24.1.
