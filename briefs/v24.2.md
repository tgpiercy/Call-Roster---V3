## 1. One-click updater
`modUpdater` (new, small, changes rarely): `UpdateFromFolder`.
- Admin only. Asks for the unzipped release folder (the one holding `modules\`, `paste-in\`, `member\`, `INSTALL.md`). Needs Excel's "Trust access to the VBA project object model"; if it is off, say exactly where to tick it and stop.
- Dated backup first (the `PeopleBackup` pattern).
- For every `modules\*.bas` except `modUpdater.bas`: remove the component of that name if present, import the file. For `paste-in\ThisWorkbook.txt` and each `paste-in\frm*.txt`: replace the code module's text (`CodeModule.DeleteLines` / `AddFromFile` or `AddFromString`). A form that doesn't exist yet: add a blank UserForm, name it, then load its code. Never touch a form's designer.
- Nothing in the updater may call into a module it is replacing while it runs. It keeps its own copies of the few helpers it needs.
- After: it cannot compile programmatically in a supported way, so it tells the admin to run Debug > Compile, then runs `SystemCheck` (via `Application.Run`, late, so it binds to the NEW code).
- A plain report: replaced, added, skipped, failed. Any failure: `MarkNoSave` and "close without saving, restore the backup, install by hand from INSTALL.md".
- `modUpdater` updates itself only by hand (INSTALL note says when). SystemCheck checks its version like the others.
- `UpdateMemberTemplate` (master side): opens the template beside the roster, swaps `modMember` and its ThisWorkbook code from the folder, runs `BuildMemberTemplate` without its confirm (add an optional quiet argument), saves, closes.
- Every INSTALL note keeps the manual steps as the fallback, after a first line "or run UpdateFromFolder".

## 2. SmokeTest macro
`modSmokeTest` (new): `SmokeTest`. Refuses to run unless `IsDryRunName(ThisWorkbook.Name)` (COPY / DRY RUN in the name). Never saves.
- Takes the before picture (`RosterTotalsMap`, `LogChargedTotal`, row counts of every table).
- Runs each step through the SAME public functions the forms call, with no pop-ups (add an optional `quiet` argument where a function shows a confirm; do not copy rule code into the test). Steps: add a test employee (`SaveNewHire`); create a posting (`CreatePostingFrom`, no print, no PDF); mark a partial and a full sign-up and submit the award (`SubmitAward`); a call-out session with a part acceptance through the same row-building code the form uses (move that code out of the form into a module function first, so there is one copy); book time off and a sick call; a shift switch; a crew change with an effective date; a unit move; rename; publish to a scratch copy of the template in a temp folder and read back `dLog`, `dRoster`, `dAttend` row counts (My history must not be empty); void everything it logged; remove the test employee; `RunIntegrity`.
- After: every person's totals and the log's charged total must equal the before picture, apart from the void rows it can list. Report one line per step: OK or the error and the procedure. The first failure stops the run.
- Test names are obviously fake ("ZZ Test, Person"); the run leaves a note in the Error Log.
- INSTALL notes replace their manual smoke test with "run SmokeTest on a copy", keeping two or three things only a person can judge (does the calendar look right, does the printout fit).

## 3. Error log
- `modErrorLog`: `LogError(proc, errNumber, errText, [detail])` appends to `tblErrorLog` on a very hidden admin sheet (When, User, Procedure, Error, Detail, Release, Seen). Never raises. `ShowErrorLog` (Alt+F8, admin).
- A helper for handlers: `ReportError proc` logs and shows "This didn't finish. Nothing was saved unless a message above said so. Tell Graeme: Error Log line N."
- Add it to the entry points first (button macros, form Submit / Save handlers, Workbook events), not to every procedure. Existing handlers that already restore state and show a message get one `LogError` line; do not rewrite them.
- Needs Attention: a line when there are unseen errors. Never published.
