## Items

### 1. Provisional accepted OT (review 1.3)
**Problem.** An Accepted call-out or Awarded posting adds no hours until Kronos catches up. Someone who just took 12 hours can be first-called again.

**Rule (decided):**
- Provisional hours count in Total Hours **from the moment the entry is logged**, even for a future shift.
- They stop counting once Kronos covers that shift.
- **Kronos data runs through the day before the import date.** Store that "data through" date on each Hours History snapshot.
- A shift is covered when it has fully ended by the end of the data-through date:
  - a day shift on date D is covered when D <= data-through;
  - a night shift starting on date D is covered when D + 1 <= data-through.

**What counts:**
- Rows that are non-void, Outcome Accepted (call-out) or Awarded (posting, including out-of-department awards).
- The amount counted is the row's shift Hours, not x 1.75.
- Only rows whose shift date falls in the current roster year count.

**Where it shows:**
- Total Hours (G) includes it, so call order, posting snapshots, the printed roster and the member publish all pick it up through the existing single path.
- Show the provisional amount somewhere visible without inserting a roster column if possible: a hidden helper or an existing spare column, a cell note, or the call-out form list. Propose the approach in the report-back.

**Done when:**
- An Accepted row moves that person down the call order straight away.
- After a Kronos import whose data-through date covers the shift, the provisional hours drop off and the worked hours take over, with no double count beyond one import cycle.
- Voiding the row removes the provisional hours.

### 2. DST nights (review 1.7)
**Rule (decided):** charge **actual hours** on the change nights.
- **Fall back:** the night that starts the Saturday before the first Sunday in November is 13 h (Sat Oct 31, 2026).
- **Spring forward:** the night that starts the Saturday before the second Sunday in March is 11 h (Sat Mar 13, 2027).
- Work the dates out by rule for any year, like `modHolidays`. No yearly table.

**Behaviour:**
- New Posting and Log Call-Out default Hours to 13 or 11 when the date is a change night and the shift is Nights.
- Show a one-line warning, e.g. "DST night: 13 h (clocks go back)". The supervisor can still type a different number.
- Day shifts are never affected.
- Add a setting, `DST_USE_ACTUAL_HOURS = True`. False keeps 12 and shows the warning only.

**Done when:** a Nights posting on Oct 31 defaults to 13 h, and a No Takers refusal on it charges 22.75.

### 3. Home Unit column (review 6.6)
- Add a **Home Unit** column to the roster, using the upgrade-macro pattern if a column insert is needed.
- Fill it automatically for anyone with exactly one unit code. Leave it blank for people with codes in more than one unit.
- Use a drop-down of the eight units.
- SystemCheck and Needs Attention list people whose Home Unit is blank. Graeme fills these in by hand.
- It's used by v22 (sick calls, leave) and v24 (unit moves). In v21 nothing else reads it.

### 4. Adjustment types (review 6.6)
- Add Add Adjustment a required **Type** list: Leave return, Unit move, New hire, Correction, Other.
- Store it so reports can separate the types. Prefer an existing log column, for example "Adjustment - Correction" in Type, over adding a column. Propose the approach in the report-back.
- Existing Adjustment rows stay as they are.

### 5. Grade change log (review 6.6)
- When a unit-code cell on the roster changes (e.g. D2 -> D1), record it in a hidden admin table, `tblGradeChange`, with these columns:
  - date and time
  - employee
  - unit
  - old code
  - new code
  - Windows login
- Use the existing `Workbook_SheetChange` routing.
- Sorting, filtering and macro writes must not create entries.
- The old value comes from a hidden snapshot that is refreshed after each recorded change.

### 6. Daily backup on first open
- On the first open of the day by an admin, call `SaveCopyAs` to save `Call Out Roster yyyy-mm-dd.xlsm` into `BACKUP_FOLDER`.
- Keep 30 days and delete older copies in that folder only, matched by the exact name pattern.
- If the folder can't be reached, show a warning and carry on. Never block opening.
- Don't take a backup on a read-only open.
- `BACKUP_FOLDER` is a setting. **The path is still needed from Graeme.** Until it's set, skip quietly and have SystemCheck flag it.

### 7. SelfTest v1 (review 3.4)
**Alt+F8 > SelfTest** runs known-answer cases and reports pass or fail per case.
- It works only on in-memory data or a scratch sheet that it deletes afterwards.
- It **never writes to the roster, OT Log or tables, and never saves.**

Cases:
- **Rotation:** about 20 dates across 2026-2027 against SHIFT2026, including the Dec 28, 2025 anchor and year boundaries.
- **Holidays:** all 11 for 2026 and 2027, plus a weekend holiday with an Observed date.
- **DST:** both change nights for 2026, 2027 and 2028.
- **Call order:** a fixed set of people, including ties on hours (seniority decides) and ties on seniority (name decides).
- **Charging:**
  - awarded;
  - ahead and didn't sign up;
  - ahead and signed up;
  - below;
  - grade 3;
  - no takers;
  - out of department;
  - two positions;
  - cancel.
- **Eligibility:**
  - rest rule in both directions;
  - A/B and C/D;
  - DAYS on a weekday, a weekend and a holiday;
  - on a switch, and having given up a shift;
  - booked off.
- **Provisional:** counted after logging; dropped once covered (day and night cases); dropped on void.

Mirror the same cases in `tests/` (Python, pytest) for the pure rules: rotation, holidays, DST, call order, charging and the provisional-coverage date logic. Both sides read the expected answers from one shared table, `tests/cases.csv`, so they can't drift apart. SelfTest gets the same values pasted in as constants.
