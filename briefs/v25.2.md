# v25.2 - Calendar speed

Written Oct 17, 2026 from `docs/deep-review-2026-10-13.md` sections 2.2 ("Calendar speed plan") and 4.7, and kit brief 06 item 3, after v25.1.1 went on the real roster. Three decisions from Graeme the same day (remote, by question): **D-C5 a full month redraw takes 3 to 10 s on the plant PC today** (so the whole plan is built, the day-only redraw included); **D-C4 the hover notes stay**; **measure first**: a measurement-only release goes in before any rewrite, so the before numbers are read off the real file, not guessed.

## What is slow (measured by reading; the numbers come from v25.1.2)
`DrawCalendar` (modCalendar, ~270 lines) for a 31-day month with ~40 lines:
- **Slots.** `SlotsFor` is called twice per day per shift (one pass for the row heights, one to write: 4 x 31 = 124 calls) plus 28 from `OpenAhead` for the Needs-attention button. Each call runs `AbsActiveOn` over every absence row (`IsDate` / `CDate` on Variants), then for each absence active that day, in the group and on the shift (`AbsenceOnShift` -> `EmpShiftOn` -> `CrewOn`; a sick call with a booked shift returns early) one full pass over the coverage rows (`CovLive`), and one final pass over the coverage rows for the lines without an absence.
- **Cells.** Every slot is written cell by cell (`WriteSlot`: ~14 property sets x 2 cells), every date cell through `DateCells` with two rich-text `Characters` edits, every row height one at a time, borders per week per day: roughly 3,000 Excel object calls.
- **Notes.** One `ClearComments` + `AddComment` + 8 shape property sets per line (`AddNote`); `LineDetails` builds the text per line (its own coverage scan).
- **Wipe.** `Rows("3:1000").Delete` over a sheet with merges and ~40 comments, then `Clear` / `UnMerge` / `ClearContents`.
- **Controls.** `BuildCalControls` deletes and re-creates 11 controls (9 buttons and 2 drop-downs) every draw (`OpenAhead` inside it).
`DrawNeeds`: ~3,000 cell calls for 50 rows, `SlotsFor` over the range, and `HomeUnitOf` (a roster scan per call: modLeave) per name and per planned move (C7).
Also on the calendar's open path (the Calendar button, admin only, before the draw): `SyncSwitchesToCalendar` re-reads the whole Coverage table once per non-void switch (C5), then `SaveIfWritable` when it added a line; and after the draw, `Done` puts calculation back to automatic (a recalculation) and the screen repaints. Not on the calendar's path but in 4.7's list: `FilterNotFree` / `SwitchPickList` re-read the Shift Switches table per person outside a publish batch (C6; their callers are the call-out and switch pop-ups, postings and the publish).

## Items, in commit order (each its own commit; the drawn sheet byte-identical to v25.1.1 unless the item says otherwise)
0. **v25.1.2 - measurement (released on its own, first).** `Timer` per phase in `DrawCalendar` (caches, wipe, header, weeks = slots / notes [the details text included] / cells, page, controls; then the recalc + repaint at Done) and `DrawNeeds` (gather with its slots share, rows, tiles); the switch sync on the open path (`ShowCalendar`) timed on its own; the breakdown kept in CalMap (Z13 the seconds, Z14 the calendar line, Z15 the Needs Attention line, Z16 the open path); the Calendar's hint cell F3 ends "Drawn in N s." (`CalHintText`, also used by `SetCalHint`); Alt+F8 > `ShowCalDrawTimes` shows the three lines. No rule, no SmokeTest change. The hand check rows ask Graeme for the numbers from the busiest month plus a stopwatch figure from the click to the screen settling (the draw's own time leaves out `CalStale` / `RosterSig` before it and the repaint after it); they go into this brief and the CHANGELOG as the "before".
1. **Slots once per day.** One pass computes `slotsD` / `slotsN` for every day of the month into arrays (31 x 2 `SlotsFor` calls instead of 124); `OpenAhead` reads the same arrays for the days it covers. Pre-normalise the absence and coverage caches once per `LoadCache` into typed arrays (dates as Long, status as Boolean, names trimmed, shift as a code) so `AbsActiveOn` / `CovLive` compare Longs; `EmpShiftOn` per (name, date) memoised for the draw. Every other `SlotsFor` caller speeds up with it.
2. **Values in one pass.** The week block's left / right texts, keys and date texts are built in 2-D arrays and written with one `.Value =` per block (`"@"` number format applied to the block first so names never turn into dates); row heights through two `Union` ranges (date rows 38, slot rows 17).
3. **Formats by class.** Cells collected into `Union` ranges per class (open, posted, covered, NCN, left text per type colour, out-of-month fill, day fill, night fill, weekend / today) and each class formatted once: ~20 applications instead of ~2,000. The date cells' rich text (`Characters`) stays per cell. Borders per week stay (7 x 2 per week).
4. **Controls once.** `BuildCalControls` creates the 11 controls (9 buttons, 2 drop-downs) only when missing (by name) and otherwise updates caption, colour, visibility and the lists; names and OnActions never change. `ApplyView` keeps toggling the `cal_adm_` shapes as today.
5. **Notes.** `AddNote` skips `ClearComments` on rows the wipe just made (they have none); `LineDetails` reads the day's slot arrays instead of scanning coverage again. The notes stay (D-C4).
6. **Needs Attention.** Name -> home unit cached in `LoadCache` (C7) and `HomeUnitOf` reads it when loaded; `DrawNeeds` writes its rows as one array per section and formats by class, as items 2-3.
7. **Day-only redraw** (built: D-C5 says 3-10 s). `MarkCalDirty` grows a dated list in CalMap (the dates touched since the last draw; "all" when a write can't say); `DrawCalendar` redraws only the week blocks holding those dates when the month and group are unchanged, the row count of each block unchanged and nothing else is stale; otherwise the full draw. The full draw stays the fallback on any doubt.
8. **Open path and the review's other speed items.** `SyncSwitchesToCalendar` reads live coverage sources into one Dictionary (C5; `CovHasSourceCached` exists); `FilterNotFree` and `SwitchPickList` run inside `BeginSwitchBatch` / `EndSwitchBatch` (C6: the pop-ups, postings and the publish, not the calendar); `UpdatePostingRecords` with events off plus one `MarkCalDirty`.
9. **Proof.** `DrawCalendarLegacy` (the v25.1.1 routine, renamed) stays for one release behind a constant; SmokeTest step 19 "calendar compare" draws the busiest month of the practice copy both ways and compares values, fills, font names / colours / sizes, merges, row heights, the CalMap keys and the comment texts, failing on the first difference; the step is removed with the legacy routine in the release after. `DrawCalendar` is split into a builder (arrays) and a writer.

Not in v25.2: any rule change (none is touched; `tests/` and SelfTest stay as they are), the Desk view, the Payroll # key (v25.3), reports (v26).
