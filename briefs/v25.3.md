# v25.3 - the Desk view for the second admin

Written Oct 17, 2026 from `docs/supervisor-desk-proposal-2026-10.md` (Oct 15; the mock-up `docs/supervisor-desk-mockup-2026-10.html`) after v25.2 went out. The four decisions of Oct 15 stand (section 6 there): `DESK_USERS` beside `ADMIN_USERS`; the Desk, zoom and tabs ship first as one install, the pop-up `UI_SCALE` pass is its own later version; five tabs for a Desk user; "Something went wrong" = an email draft to the primary admin with the newest Error Log line. One install (v25.3); what its testing turns up goes into the next bundle.

## Checked against the code (Oct 17)
- **Views today are two** (`ApplyViewCore`): admin (16 admin sheets visible, phone / email / Payroll # columns shown, the `ui_adm_` bar shapes visible, the `cal_adm_` Calendar buttons visible, roster cells unlocked per `LockRosterCells`) and everyone else. Needs Attention and Postings are in the admin-only sheet list, so the Desk mode has to show those two on its own (the proposal's five tabs: Desk, OT Roster, Calendar, Needs Attention, Postings).
- **The bar** (`BuildCommandBar`): a non-admin sees the 9 sort buttons, Log Call-Out and Calendar; Shift Switch and Book Time Off sit in the LOG group as `ui_adm_` buttons, so a Desk user reaches them from the Desk only (as the proposal says). `ApplyRosterLayout` rebuilds the bar: the one new "< Desk" button on the master bar comes with a one-time macro run on install (the panel's group 3).
- **Opening** (`ThisWorkbook.OpenStep` case 10 activates the roster): the Desk user lands on the Desk instead -> ThisWorkbook changes (so `THISWB_RELEASE` moves to v25.3 and the panel re-pastes it). Zoom on activate (roster and Calendar at 120 % for Desk users) is a `Workbook_SheetActivate` line routed to modDesk.
- **The four tiles have sources, but not as functions:** shifts needing cover = `OpenAhead(grp, 14)` (Private in modCalendar; per group - the Desk tile wants all groups: a loop over `CalGroupNames()`); postings ready to award = `nReady`, a local counted inside `DrawNeeds` (not reusable: the counting goes into a small Public `ReadyToAwardCount()` in modCalendar that `DrawNeeds` and the Desk both call); paybacks owed = `OwedSwitches(ids)` (Public, modShiftSwitch); members' file age = the publish timestamp `DrawNeeds` section G reads (`pubAt`): the same read goes into a Public `MembersPublishedAt()`; Kronos age and the pay period = what `SetRosterStatus` (modUI) already works out (`KronosDataThrough`, `PeriodStartFor`).
- **The email draft:** modPostings has the Outlook `CreateItem(0)` path and the `mailto:` fallback for award emails; "Something went wrong" reuses that pair (one Public entry point exposed if the current one is Private) with the newest Error Log row (`modErrorLog`, the table's first data row) in the body.
- **Checks:** `N_MODULES` 24 -> 25 (modDesk stamped); `FORM_RELEASES` untouched (no form changes in v25.3); SelfTest + `tests/` get a suite for the one pure decision, `ViewModeFor(login, adminList, deskList)` -> "desk" / "admin" / "user" (a login on both lists = desk with admin rights; the primary admin on ADMIN_USERS alone = admin); the tile counts are read from the roster's own functions, so they are proven by SmokeTest (a step that reads the four counts, changes something - the existing posting / switch steps already do - and reads them again) rather than by known-answer cases.
- **Protection (v25):** the Desk sheet is drawn by code like the Calendar (UnlockSheet / ProtectSheet around the draw; shapes with OnAction; `SetTabColor`); it is added inside `UnlockStructure` / `RelockStructure`; `ProtectAll` covers it; a Desk user types nowhere (his roster cells are unlocked only if he is on ADMIN_USERS too - he is, per decision 1).
- **Saving:** `Workbook_BeforeSave` stores the restricted view; `SaveRestrictedCopy` the same. A Desk user's open therefore starts from the restricted view and `ApplyView` puts his Desk mode on; the file never saves "in Desk mode".

## What is built (one commit per item)
1. **`modDesk` (new, stamped):** `DESK_USERS` (settings line beside `ADMIN_USERS` in modOvertimeEntry), `IsDeskUser`, pure `ViewModeFor`; `BuildDesk` (draws the sheet: header band with today, the pay period and "Kronos data through <date>" red when over 7 days old; the TODAY tiles; the RIGHT NOW / PLAN AHEAD / PEOPLE / WHEN YOU ARE DONE / HELP groups with the 14 verb-phrase buttons at 12 pt on 36-pt shapes, the two footer links), `RefreshDesk` (recounts the tiles; called on open, on the Desk's activate and after the pop-ups the Desk opened return), the 14 `Desk*` OnAction wrappers (each a framed entry point calling the existing macro: `ShowSickCallForm`, the call-out form, `ShowCalendar`, `ShowNewPostingForm`, `ShowPostingForm`, `ShowTimeOffForm`, `ShowShiftSwitchForm`, `ShowLeaveForm`, `PublishMemberView`, `Call_Out`, the guide, the email, `ShowNeedsAttention`, "Show everything"), `DeskGuide` (opens `GUIDE_PATH` when set, else a box that says to ask the primary admin), `DeskReport` (the email draft).
2. **The Desk mode in `ApplyViewCore`:** a third state - admin rights (unlocked cells, the pop-ups' gates pass) with supervisor visibility PLUS Desk, Needs Attention and Postings; the `ui_adm_` groups PEOPLE / POSTINGS / PRINT-PUBLISH / ADMIN hidden, LOG's Shift Switch and Book Time Off hidden, the "< Desk" button shown; the Calendar's `cal_adm_` buttons shown (he is an admin). "Show everything" = `ApplyView True` for the session with the Desk sheet still reachable; "< Desk" on the master bar = back to Desk mode. `ApplyView` keeps its error frame; `ProtectionStatus` and SystemCheck's "Protection" line count the Desk sheet.
3. **ThisWorkbook:** open step 10 activates the Desk for Desk users (else the roster as today); `Workbook_SheetActivate` sets the zoom (120 % on OT Roster and Calendar for Desk users, 100 % otherwise, once per activate) and refreshes the Desk when it is activated. `THISWB_RELEASE` -> v25.3.
4. **The master bar:** "< Desk" (`ui_Desk`, visible to admins and Desk users; the primary admin uses it to see what the other admin sees); the install's one-time macro `ApplyRosterLayout`.
5. (Dropped Oct 17, D5: no form changes in v25.3. The three 8 pt texts in the Callout Session pop-up go to 10 pt with the UI_SCALE version, where every pop-up is re-checked on his screen.)
6. **SmokeTest step:** "the Desk's tiles follow the data" - read the four counts, after the posting / switch steps they must have moved as expected, and `ViewModeFor` for three made-up logins.
7. **Docs:** `docs/desk-guide.md` (one page for him: the screen, the five tabs, "Show everything", "Something went wrong"); the supervisor quick guide gains a Desk paragraph; the admin install guide's view table gains the Desk mode; `INSTALL-v25.3.md`, `steps-v25.3.txt` (group 3: `ApplyRosterLayout`; group 4: open as a Desk user on a copy - `DESK_USERS` must carry a test login, or the primary admin clicks "< Desk" and checks the screen).
