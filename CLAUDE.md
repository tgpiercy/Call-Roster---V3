## What this is
An Excel desktop `.xlsm` (VBA) overtime call-out system for Syensqo's Niagara Falls phosphine plant.
- **Master file:** `V2 - Call Out Roster.xlsm`. Main tab `OT Roster` (setting `ROSTER_SHEET`; the code also finds it by headers).
- **Owner / maintainer:** Graeme (shift supervisor, admin). 8-10 supervisors use it, one at a time.
- **Units:** Phosphine, Derivatives, Cypure, Material Handler (Fumigation, called "Gases"), QC Lab (QC Derivatives), QC Gases, Utilities, SBP.
- **Plant terms:** NCN = No Coverage Needed. S/S or SS = shift switch. PHA = hazard-analysis coverage. 12-hour shifts, days 7 AM-7 PM, nights 7 PM-7 AM, nights dated by the evening they start.

**Nothing in this repo can be run.** There is no Excel here. Graeme imports the code, runs Debug > Compile, and tests by hand on a copy. So:
- Write compile-safe VBA (`Option Explicit` everywhere) and review it as if no compiler will check it.
- Prefer small, verifiable changes over rewrites.
- Anything that changes data runs a before/after check and blocks the save on a mismatch.
- **This repo is the single master for the code.** Nothing is installed from anywhere else; every release is built from a tagged commit.

## Repo layout
```
modules/     *.bas  standard modules (file name = VB_Name), imported via File > Import
paste-in/    *.txt  code for ThisWorkbook and each UserForm (pasted with Ctrl+A); no Attribute lines
member/      the members' workbook: modMember.bas + its ThisWorkbook.txt (a separate .xlsm, no master names)
updater/     modUpdater.bas: the Roster Updater + Install panel (v4), imported into its OWN workbook (never into the roster)
briefs/      one brief per update (v21.md, M1.md, v22.md ...); from v24.4 also steps-vNN.txt = groups 3-4 of that release's install-steps.txt
docs/        planning docs, install notes (INSTALL-vNN.md), report-backs, the code kit as supplied
tests/       Python mirrors of the pure rules + known-answer cases + static checks (see Tooling)
dist/        built zips (gitignored)
CHANGELOG.md
```
**Never commit data:** no `*.xls*`, Kronos exports, posting PDFs or plant CSVs (names, phones, emails, leave codes). Test fixtures use made-up names only.

## Canonical business rules
These win over anything older in `docs/`. Each rule lives in **one** function that forms, printouts, Needs Attention and the member publish all call. If you find a second copy, consolidate it instead of patching both.

**Call order:** grade code (in that unit's column) -> Total Hours G (lowest first) -> Plant Seniority J (earliest first) -> name. Implemented once: `LoadEligible` / `SortEmpRecs` (modOvertimeEntry). Used by the call-out form, the posting list, the printed roster, the member publish.

**Total Hours** = Kronos worked hours (H) + non-void Hours Charged in the OT Log for the current year **whose pay period has started** (I; v26.5, Graeme Oct 19: `RefusedFormula` counts Period Start <= the hidden name `RefusedThrough` = the current period's start, moved on every open; a posting refusal for a shift two periods out shows in its period column and starts counting when that period begins - a call-out's charge carries the pay period of the shift it was for, so a call-out for a shift in a later period waits the same way - rare, call-outs are mostly same-day; Graeme confirmed Oct 19: one rule for both) + provisional accepted OT (C): Accepted call-outs and Awarded postings count from the moment they are logged, even for a future shift, until Kronos covers the shift. Kronos data runs **through the report's Time Period end** (`KronosDataThrough`; v27 - before, the day before the file's saved date, which the pivot-sheet fall-back still uses). A day shift on D is covered when D <= through; a night on D when D + 1 <= through. **Worked (H) itself (v27, `briefs/v27-kronos.md`)** = the Kronos Totals snapshot (the last cumulative report) + the Worked Days ledger (the one-day reports after it), each code's hours x its multiplier (`PREMIUM_CODES` / `PREMIUM_MULTIPLIERS`), rounded whole per person (`WeightedTotal`): the straight-time equivalent Graeme's processing workbook computed.

**Who's listed (call-outs and postings):** anyone with a code in the unit's column, **any grade**, who is free for that date and shift (`NotFreeReason` in modCalendar). Not free when:
| Reason | Rule |
|---|---|
| Scheduled | Crew on that shift per rotation. A/B and C/D work their pair's **day** shifts whenever either is on days, never nights. DAYS = Mon-Fri days, **off on plant holidays** (observed date). **The crew is the one the person is on THAT DATE** (v24: `CrewOn`, crew history). |
| Rest rule | Day OT: crew coming off nights that morning. Night OT: crew starting days next morning. A switch worked the night before / day after counts. |
| Booked off | Absences row covering the date (not imported calendar lines, which are display only until converted in v22). |
| Switch | Working a switch that day, or gave up a shift that day (not free for the other shift either, D-C1/C2). v25: a shift GIVEN UP in a switch relieves the next day's rest rule - they did not work it (D-C3). |
| Sick window (v22 / v25) | Off any shift starting within 24 h after the sick shift ends; v25 (D-L1): inside the window they may neither work nor give up a shift in a switch. |
| OT restricted (v27 item 21, Graeme Oct 21) | An admin's restriction row (`tblRestrictions`, From / To / reason; `OtRestrictedOn`): not listed for call-outs or postings while it runs (`FilterNotFree`, the out-of-department award, `SyncPersonOnPostings`; a posting frozen BEFORE the restriction marks the row exempt at award LOAD, so it is never charged), **never charged**, nothing published; the calendar, the staffing count, the switch rules and the 16 h hard stop ignore it - it is a LIST rule, never inside `NotFreeReason`; a rename follows it. Entered through the Employee pop-up's Edit (OT restriction...) or Alt+F8 `RestrictOT`; ended by `EndRestriction` (voided with a note). Needs Attention lists the active ones. |
| Weekly cap (v27 item 21; the Oct 19-20 decision: a warning, never a block; **OFF since Oct 22 - Graeme: the 48 h is a limit on scheduled work, overtime is requested; `WEEK_MAX_HOURS` 0, a Settings number turns it on**) | An acceptance or an award that takes a person's OVERTIME past `WEEK_MAX_HOURS` (48; the Settings sheet may override it) in the 7 days before the shift (`WeekHoursBefore`: accepted call-outs and awards from the log through `OtWorkedOn`; scheduled shifts are not counted - the rotation alone holds 48-60 h in many windows; pure `WeekCapOver`, suite `weekcap`) warns and takes a reason into the log row's Reason (a Cancel in the reason box logs nothing and leaves a partial's hours as they were) (`[over 48 h/week: ...]`; `PListRec.OverrideNote` for awards). |
| 16 h rule (v26.5.5, Graeme Oct 19-21) | Accepted call-outs, awards and switches are WORKED shifts. The consecutive work that ENDS when the offer starts (the touching shift plus the one before it whenever both were worked; a partial counted whole) plus the offer may not pass `FATIGUE_MAX_HOURS` (16), and the offer's start must leave `FATIGUE_MIN_REST` (11 h) before the next work (scheduled or accepted, the next two shifts looked at in 12 h steps). ## Engineering conventions
1. **Versioning.** Every module has `Public Const X_VERSION As String = "Name vNN (Mon d)"`; forms and ThisWorkbook have the `' @version` line; `modSystem.EXPECTED_RELEASE` is the release and `N_MODULES` the count. Bump every module that ships, and the expected release, in the same update. SystemCheck must say "N of N on vNN". **Numbers (Graeme, Oct 17, 2026, restated Oct 20 to match practice; the aim is FEWER INSTALLS): `vNN` = a feature or major release (v26 the beta build, v27 the pre-training bundle); `vNN.5` = the revisions after testing that release, one install (v25.5 the alpha build, v26.5 the post-beta revisions); `vNN.5.x` = fixes to that, batched (v26.5.5), never installed alone unless the roster is broken. What turns up during a test waits for the next bundle or feature release.** (The one-install-per-fix pattern of v25.1 / v25.1.1 / v25.1.2 on Oct 16-17 is what this rule stops.)
2. **Append-only log.** Never edit or delete OT Log rows. Corrections are voids (Status VOID, Void Note) plus a new entry. Never type hours into roster cells; they are formulas over the log. The ONE sanctioned removal is `RolloverYear` moving a closed year's rows to its `OT Log YYYY` sheet, verified. (Roster ROWS are removed only by `RemoveEmployee`, verified, and names are changed only by `RenameEverywhere`, which rewrites the Employee column of the log and every other table together - v28: by the Payroll # key where a row carries it, `KeyMatchCore`.) Because of it, IDs come from `NextRefID` / `NextEntryID` (which honour the `IdMark_*` high-water marks): never work out a next ID by scanning the log yourself.
3. **Verified data changes.** Any macro that restructures data: dated backup first -> change -> compare every roster period, Refused (I) and Total (G) value and the log's total Hours Charged before vs after -> on mismatch, `MarkNoSave` and tell the user to close without saving. Copy `UpgradeOTLogLayout` / `RunMigration` / `SetupHomeUnit`.
4. **Read every row, whatever the view.** Use `ListObject.DataBodyRange` or the roster's cell reads, never last-visible-row. Handle `DataBodyRange Is Nothing`.
5. **Columns.** Roster and log columns are constants in modOvertimeEntry (`C_*`, `L_*`); use them. For anything new, find by header text where the code already does that. **Crew (v24): never read roster column E to answer a question about a date.** Use `CrewOn(emp, d)`, `EmpCrewCode(emp, d)`, `EmpShiftOn(emp, d)` or `LoadEligible(..., asOf:=d)`. Column E is the newest crew, for display. Code that writes column E turns events off and adds the crew row itself (`AddCrewRow`). **Unit codes (v24.3): a roster unit column is the code TODAY.** To ask whether someone holds a code in a unit on a date, use `LoadEligible(..., asOf:=d)` or `UnitCodeOn(emp, unit, d, rosterCode)`, which count a waiting planned move from its date. Display code (sorts, the Former sheet, the publish's Roster table, the peer lists for a top-up) reads the column as it is.
6. **Bulk work:** turn off ScreenUpdating, EnableEvents and calculation, and restore them in an error handler on every exit path. Capture the "was" values **before** `On Error GoTo`.
7. **Calendar dirty flag:** writes to Absences, Coverage, Postings or Shift Switches with events off must call `MarkCalDirty`.
8. **Late binding only** (Outlook, Scripting). No new references.
9. **Dates:** build with `DateSerial`; parse typed dates through `ParseTypedDate` / `TypedDateHint` in modDates (v27.1; modPeople before) (v25: the ONE parser, pure `TypedDateCore`, read by hand - never CDate: "Oct 12", "12 Oct 2026", "10/12" as month/day, a typed time ignored; a yearless date lands in the year that puts it inside today-90 .. today+275, so "Jan 5" in December is next January and "Dec 20" on Jan 3 is last December), pre-fill a date box with `DateText`. Never `CDate` a locale-ambiguous string. Cells that hold month or date **text** get `NumberFormat = "@"` first, or Excel converts them.
10. **Gating.** Three levels by Windows login. **ADMIN** = a login on `ADMIN_USERS` (`RequireAdmin`; buttons `ui_adm_`, hidden for others): time off, switches, leave, void, Undo last, adjustments, people, Kronos, a posting's reopen / No Takers / Award Out of Dept / Cancel Request (the three `Submit*` carry `RequireAdmin` before `CanFinalize`), Employee > Edit (a double-click on a roster row; quiet for anyone else). **SUPERVISOR** (v25.5, Graeme Oct 18) = a login on `SUPERVISOR_USERS` (mihaychukc, sheltond, campeauc) or an admin, `IsSupervisor` / `RequireSupervisor` (refuses anyone else by name, and a read-only copy): log a call-out, book a sick call (`ShowSickCallForm` / `SaveAbsence`), post a shift (`ShowNewPostingForm` / `CreatePostingFrom`), award a posting to the list (`ShowPostingForm` / `CanFinalize`), print the call-out roster (`Call_Out`), publish the members' file (`PublishMembers`); buttons `ui_sup_`; the award pop-up greys the three admin buttons for them. **PLAIN USER** = anyone else: log a call-out, the calendar, the sorts (`ui_btn_`); lands on the roster. (v25.3's "any editor is a supervisor" lasted one day; v25.5 replaced it.) Oct 19: plant PCs use personal Windows logins, so the login is a reliable identity.
11. **Flat, list-shaped tables** (one header row, stable names, no merged cells) so they can become SharePoint Lists later.
12. **Messages** tell a supervisor what to do next, in plain words.
13. **Names are an interface.** Public procedure names that buttons call (OnAction in `BuildCommandBar`) and macro names in install notes don't change. If a rename is unavoidable, `ApplyRosterLayout` must rebuild the buttons and the install note must say so.
14. **File format:** CRLF and ASCII only in `.bas` and paste-in `.txt` (`.gitattributes` enforces CRLF; write `->`, `-`, `...`). Every `.bas` starts with `Attribute VB_Name`. Every file has `Option Explicit`.
15. **Entry points catch errors (v24.2).** A button macro, a macro that opens a pop-up, or a workbook event starts with `On Error GoTo Oops` and ends `Exit Sub / Oops: / ReportError "Name"`. Inside it, restore a handler with `On Error GoTo Oops`, never `On Error GoTo 0`. A handler that already restores state and shows its own message adds `LogError "Name", Err.Number, em` right AFTER it has captured `em = Err.Description` (LogError clears Err). An error inside a pop-up travels up to the macro that opened it. `ReportError` (v24.3.1) puts ScreenUpdating, EnableEvents, the cursor, Calculation (automatic), the status bar and DisplayAlerts back and re-protects the roster, so a handler that reaches it needs nothing else; a handler that restores its own captured calculation mode still should.
16. **SmokeTest switch (v24.2).** `gSmokeRun` is True only while SmokeTest runs on a practice copy. New confirms on a path SmokeTest uses go through `Ask(prompt, buttons, title, smokeAnswer)` and success messages through `Tell`; `SaveIfWritable` does nothing while it is on. Never test `gSmokeRun` to change a rule.
17. **Protection (v25, R4).** Every sheet is protected in every view; `ProtectSheet ws` always protects (the Install Log sheet excepted; `AllowSorting` off, `AllowFiltering` on). A write to a sheet is `UnlockSheet ws` ... `ProtectSheet ws`; `UnlockSheet` and `UnlockStructure` hold the only Unprotect of a roster sheet (modPublish unprotects the members' file; test_drift checks). `ReportError` runs `ProtectAll`, so a handler that reaches it needs nothing else. **v26.5 (Graeme, Oct 19): nothing on the roster is typed into** - `LockRosterCells` locks every roster cell in every view; a person's details change through the Employee pop-up's Edit (a double-click on the row, `SaveEmployeeEdit` the one write path), Worked (H) through the Kronos import; v27 (item 33): the Holidays "Observed on" cells and the Min Staff sheet's Minimum / Note are locked too (`LockHolidayCells` / `LockMinStaffCells` lock every cell; the admin Desk's Holidays / minimum staffing opens `frmTableEdit`); the Reconcile sheet's typed order and the Rules sheet's Basis column (`LockRulesCells`) are the only typed-into cells left; everything else goes through buttons, and a message that asks for a hand edit appends `ByHandHint(sheet)`. `ApplyView` is the framed entry point; `ApplyViewCore` raises (SaveRestrictedCopy, the updater's probe). A sheet is added, deleted, renamed or shown / hidden inside `UnlockStructure` ... `RelockStructure` (`SetSheetVisible` for visibility); a tab colour is set through `SetTabColor` (v25.1). The very-hidden `CalMap` sheet is written through `MapWrite` (v25.1), never bare. Every copy of the roster leaves through `SaveRestrictedCopy`.

### VBA compile and runtime traps to check in review
- `Dim a, b As Long` makes `a` a Variant. Declare each.
- Max 24 line continuations per statement; 64 KB per procedure. Split big builders.
- Use `Long` for row counts, not `Integer`.
- Duplicate procedure names across modules -> "Ambiguous name". Search before adding a Public name.
- **A local or parameter with the same name as a procedure hides it** (names are case-insensitive): `tests/shadowcheck.py` finds these. Avoid helpers named `S`, `N`, `D`, `P`, `F`.
- `Lock`, `Unlock` and other reserved words can't be procedure names. Data-type and built-in names can't be variables either: `Single`, `Date`, `String`, `Long`, `Len`, `Int`, `Abs`, `Input`, `Type`, `Write` ... (`Dim single As Long` is a syntax error).
- One-line `If ... Then x ElseIf ...` is a compile error; use a block If.
- `ReDim Preserve` can only grow the **last** dimension; size 2-D tables up front.
- Module-level variables must be declared above the first procedure.
- Inside a Function, its own name followed by `(...)` on the LEFT of `=` is a CALL to itself (`SerialSet(key) = True` recursed until the stack ran out - v27.5 review; it compiles when the function returns Object): build the result in a local, then `Set Name = local`. callcheck SELFCALL flags the shape.
- Code-built forms: control names must be unique; `WithEvents` handlers need the module-level `WithEvents` pattern already used.
- `Application.Match`/`VLookup` return errors, not raise them: test with `IsError`.
- Excel auto-converts text like "Oct 2026" or "Mon Oct 12" written to a General cell into a date.

## How every update ships

2. **Report back before writing code:** check every (verify) item against the code; ask real decisions as **multiple-choice questions** (AskUserQuestion), offering the brief's default first. Wait for a go-ahead.
3. Build to the brief, one commit per item.
4. **Independent review** of every changed file by a separate read-only agent that didn't write it: compile traps above, rule consistency with this file, filter/visible-row bugs, events/calc restored on every exit path, privacy, no new write paths to the roster or OT Log outside the existing ones. Fix, then re-review the fixes.
5. Add SelfTest + `tests/` cases for every rule touched.
6. Tag `vNN` (annotated), then package `dist/Callout_Roster_vNN.zip` (full set + `install-steps.txt`) with `INSTALL-vNN.md` and `briefs/steps-vNN.txt`: `build_zip` refuses a HEAD that isn't tagged vNN and stamps the tag into the note. From v24.4 the step list IS the install (the Install panel in Roster Updater.xlsm runs it: backup, swap, compile, finish + reopen, the run-once macros, the hand checks as Pass / Fail rows); the INSTALL note is "what's new" plus "open the panel" and one line pointing at the panel's own by-hand fallback. A release that changes `updater/modUpdater.bas` says so: that one file is imported into Roster Updater.xlsm by hand.
7. Update `CHANGELOG.md` and the affected `docs/` (before the tag); push main and the tag to the private remote `origin` (https://github.com/tgpiercy/Call-Roster---V3, set up Oct 14, 2026; the push runs in Graeme's Terminal panel with his approval).

**Install freezes:** no updates Dec 20 - Jan 4 except the rollover; none in the week before Jan 23, 2027.
