## C3: Member View still refused after the posting was cancelled
**The refusal is correct; the guide's expectation was wrong.** A posting writes its Reason as the need text of its calendar line (`CalendarPosted` -> `CalendarPlace` -> `AddCoverage`). `SubmitCancel` sets that line's coverage to NCN (`UpdateCoverageBySource`) and keeps the text, so "covering J. Smith STD" was still going to the members' calendar (`BuildCal` -> `SlotsFor` -> `LeftText`), and `LeaveCodesIn` named it: `dCal row 91 (Oct 15 Nights Cypure): the text says 'STD'`. The calendar is screened before the posting table, so the first refusal (dPost) means the line was not carrying the words at that publish (not yet on the calendar, placed on another line, or outside the publish window) and the second (dCal) that it was by then; how P-0011 was placed is a question for Graeme, not a code question. There was no button to change a line's text or a posting's Reason; the only way was typing on the Coverage or Postings sheet in admin view.

**Fix (Graeme chose it over a message-only fix and over blanking the text at cancel):** the line's double-click menu gains **Change the text of this line...** for admins, on need ("C:") lines only (a time-off line's text is the name, the kind and the times note from the booking). `SetLineText` (modCalendar) screens the new text with `LeaveWordsIn` and refuses a leave word with the word named, writing nothing; otherwise it writes the line's need text and, when the line's source is a posting that is still Open, that posting's Reason too (`modPostings.SetPostingReason`; a closed posting's Reason is not published and is left alone). The refusal box now ends with where the word lives and which button fixes it (`CalFixHint` in modPublish, from the slot key `BuildCal` keeps per row: the line and its source posting; Set coverage for a covered-by; Book Time Off for a times note). SmokeTest step 9 exercises the refusal and the change on its own posting's line before the cancel.
